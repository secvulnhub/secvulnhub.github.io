Overview

What websec does

websec is a terminal-based web security research tool for bug bounty hunters and security researchers. It covers the full recon-to-exploitation workflow: passive OSINT, security posture auditing, misconfiguration testing, and lightweight vulnerability probing. Every operation prints a [LEARN] section explaining what the check is, why it matters, and where to go deeper.

The tool works out of the box with Python stdlib only. Optional dependencies (requests, beautifulsoup4, dnspython) unlock additional capabilities without breaking anything if absent.

OSINT
Web Recon
DNS records, WHOIS, SSL cert transparency (crt.sh), robots.txt, Wayback Machine, and tech stack fingerprinting.
Headers
Security Headers
Audit HSTS, Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, and server version disclosure.
CORS
CORS Testing
Detect wildcard origins, reflected Origin headers, and credential-enabled CORS misconfigurations that enable cross-origin attacks.
Cookies
Cookie Audit
Check Secure, HttpOnly, and SameSite flags on all cookies. Flags session cookies missing protection against theft and CSRF.
Discovery
Directory Brute
100+ built-in paths covering admin panels, config files, backups, and exposed version files. Custom wordlist support.
SQLi
SQL Injection
Error-based detection across 15+ database error patterns (MySQL, PostgreSQL, MSSQL, Oracle, SQLite). Safe payloads only.
XSS
Reflected XSS
Test input parameters for reflection without HTML encoding. Detects contexts where a payload would execute.
Spider
Web Crawler
Crawl the site up to a configurable page limit. Maps URLs, forms, JS file references, and external links.
WAF
WAF Fingerprint
Detect Cloudflare, AWS WAF, ModSecurity, Akamai, Imperva, F5 BigIP, and Sucuri from response headers and body patterns.

Quick Start

Running websec

# Start with recon - passive, non-intrusive
secV ❯ use websec
secV (websec) ❯ set operation recon
secV (websec) ❯ run https://example.com

# Security headers audit
secV (websec) ❯ set operation headers
secV (websec) ❯ run https://example.com

# SQLi on a parameterized URL
secV (websec) ❯ set operation sqli
secV (websec) ❯ set test_url https://example.com/search?q=test
secV (websec) ❯ run https://example.com

# Full assessment - all non-intrusive checks
secV (websec) ❯ set operation full
secV (websec) ❯ run https://example.com
! Authorization required. Only test systems you own or have explicit written permission to test. Bug bounty hunters must read and respect scope before running any checks.

Reference

Operations

Set via set operation <name>. Default is recon.

recon default
Full passive OSINT: DNS A/MX/NS/TXT records, WHOIS registrant data, SSL certificate inspection (crt.sh subdomains), robots.txt, Wayback Machine snapshots, and technology stack fingerprinting.
headers
Audit HTTP security headers. Checks HSTS, Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy. Flags server version disclosure via Server and X-Powered-By headers.
cors
Test for CORS misconfigurations by probing with a null origin, attacker origin, and subdomain origin. Detects wildcard Access-Control-Allow-Origin, reflected origins, and Access-Control-Allow-Credentials: true with unsafe origins.
cookies
Parse all Set-Cookie headers and check each for Secure flag (sent only over HTTPS), HttpOnly flag (no JS access), and SameSite attribute (CSRF protection). Reports cookies missing each flag with severity context.
dirs wordlist
Brute-force paths using 100+ built-in entries covering .env, .git, admin panels, backup files, config endpoints, and debug routes. Supply a custom wordlist via wordlist_file for larger sweeps.
sqli test_url
Error-based SQL injection detection. Tests each query parameter with payloads for 15+ database error patterns (MySQL, PostgreSQL, MSSQL, Oracle, SQLite, DB2). Uses safe detection-only payloads - no data modification.
xss test_url
Reflected XSS detection. Tests query parameters for unencoded reflection of a probe string. Detects HTML context injection and identifies parameters where a payload would execute in the browser.
spider max_pages
Crawl the site breadth-first up to max_pages (default 50). Collects all internal URLs, form actions, JS file references, and external links. Stays within the same domain - no cross-origin crawling.
dork
Generate 18+ Google dork queries for the target domain: exposed configs, login pages, sensitive file types, cached content, and related subdomains. Also links to Shodan, crt.sh, Wayback Machine, and other OSINT resources.
ssl
Deep SSL/TLS analysis: negotiated protocol version, cipher suite, certificate subject/issuer/SANs, expiry, and whether the site enforces HTTPS redirect. Flags TLS 1.0/1.1 and weak cipher usage.
waf
Fingerprint WAF presence and type from response headers (cf-ray, x-amzn-requestid, x-sucuri-id, etc.) and body patterns. Detects Cloudflare, AWS WAF, ModSecurity, Akamai, Imperva, F5 BigIP, and Sucuri.
full
Run all non-intrusive operations: recon + headers + cors + cookies + dirs + ssl + waf in one pass. Output is combined into a single findings report with severity-sorted results.
vulnlib
Browse the built-in OWASP vulnerability knowledge base. Covers OWASP Top 10 entries with descriptions, impact, detection approach, fix recommendations, and links to PortSwigger Web Security Academy and OWASP resources.

Reference

Parameters

ParameterTypeDefaultDescription
operation string recon Operation to run. See Operations section above.
test_url string — Full URL including query parameters for SQLi and XSS testing. E.g. https://example.com/search?q=test. Required for sqli and xss operations.
threads integer 10 Concurrent threads for directory discovery. Range 1-50. Higher values are faster but more detectable.
timeout number 10.0 HTTP request timeout in seconds. Range 3.0-30.0.
max_pages integer 50 Maximum pages to crawl in the spider operation. Range 1-500.
wordlist_file string — Path to a custom wordlist file for directory discovery. One path per line. Falls back to the built-in list if not set.
verbose boolean false Enable verbose output. Shows all requests, including negative results, during discovery operations.

Installation Tiers

websec degrades gracefully. Core operations work with Python stdlib only. Install optional packages to unlock the full feature set.

Basic
stdlib only
DNS lookup, WHOIS, SSL inspection, security headers, robots.txt, directory brute-force, WAF detection, Google dorks, vulnlib. No install required.
Standard
+ requests
Full HTTP session handling, CORS testing, cookie analysis, SQLi detection, XSS detection, WAF fingerprinting. pip3 install requests
Full
+ beautifulsoup4
HTML parsing for spider/form detection, JS file enumeration, link extraction, XSS in form inputs. pip3 install beautifulsoup4
# Full install
pip3 install requests beautifulsoup4 dnspython

Notes

Notes

! Authorization required. Unauthorized testing may violate the CFAA, Computer Misuse Act, and equivalent laws globally. Always get explicit written permission. For bug bounty work, read the program scope before running any checks.

SQLi and XSS tests use safe detection payloads only. They send crafted strings to detect error messages or unencoded reflection - no data is modified, deleted, or exfiltrated. Time-based blind SQLi is not included.

The dork operation generates query strings for manual use in Google - it does not interact with Google's servers. Copy the output and run searches manually.

For deep SSL analysis, pair with ssllabs.com/ssltest. For manual testing after automated checks, Burp Suite Community (free) provides a proxy and repeater for inspecting requests and responses directly.

The [LEARN] context printed by each operation references PortSwigger Web Security Academy and the OWASP Top 10 for deeper reading on each vulnerability class.
