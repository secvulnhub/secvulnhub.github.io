Overview

What wifi_monitor does

wifi_monitor is SecV's real-time WiFi network monitoring module. It discovers all active hosts on a subnet using ARP broadcasts (scapy) with automatic TCP-ping fallback when running without root. For each discovered host it runs an async port scanner, grabs SSL certificates, HTTP headers, and SSH banners, fingerprints the device type, and cross-references open services against the CIRCL CVE API.

The threat detection engine automatically flags critical exposures — databases open to the network, cleartext protocols like Telnet and FTP, default credential services, and end-of-life SSH versions — giving you a prioritized risk picture without manual triage.

Discovery
ARP + TCP
ARP broadcast via scapy for fast L2 discovery. TCP-ping fallback for non-root environments.
Scanning
Async Ports
Concurrent async port scanner. SSL cert grab, HTTP header pull, SSH version banner — per host.
Intel
CVE Lookup
CIRCL CVE API with 24h local cache. Keyword search per detected service/vendor.
Classify
Device Types
Auto-fingerprints IoT cameras, routers, NAS, databases, web servers, Linux hosts.
Risk
Threat Flags
Critical: exposed DB, Telnet, FTP. Warning: EOL SSH, default-cred services, unencrypted admin.
Output
JSON Report
Structured per-host JSON: ports, banners, device type, CVEs, threat flags, summary stats.

Quick Start

Running a scan

wifi_monitor reads a JSON context from stdin — target is the subnet CIDR or single IP, params controls scan depth and features.

# Basic subnet scan — ARP discover + port scan + CVE lookup
sudo secV
secV ❯ use wifi_monitor
secV (wifi_monitor) ❯ run 192.168.1.0/24

# Deep scan with all CVE lookups
secV (wifi_monitor) ❯ set mode deep
secV (wifi_monitor) ❯ set cve_lookup true
secV (wifi_monitor) ❯ run 192.168.1.0/24

# Direct stdin invocation
echo '{
  "target": "192.168.1.0/24",
  "params": {
    "mode": "monitor",
    "ports": "top-20",
    "port_scan": true,
    "cve_lookup": true,
    "concurrency": 50
  }
}' | python3 wifi_monitor.py | jq .

# Passive only — discovery no port scan
echo '{"target": "10.0.0.0/24", "params": {"mode": "passive", "port_scan": false}}' \
  | python3 wifi_monitor.py
! Run as root for ARP scanning (required for scapy L2 broadcasts). Without root, TCP-ping fallback is used — slower and may miss some hosts.

Reference

Scan modes

The mode parameter controls what runs — discovery only, port scanning, banner grabbing, and CVE enrichment depth.

monitor default
ARP discovery + top-20 port scan + SSL/HTTP/SSH banners + device fingerprint. Balanced.
passive quiet
ARP discovery only — no port scanning, no banners. Just which hosts are alive and their MACs.
deep thorough
Full discovery + top-100 ports + banners + CVE lookup for every detected service. Slower.

Parameters

All parameters go in the params object of the JSON stdin input.

Device fingerprinting

wifi_monitor classifies each host into a device category based on open ports, HTTP headers, SSL certificate subjects, and SSH banners. This determines which CVE keywords are searched and which threat checks run.

Category
IoT Camera
Ports: 554 (RTSP), 8080, 8888
Signals: RTSP stream headers, IP cam HTTP UI
Category
Router / Gateway
Ports: 80, 443, 53, 23
Signals: Router/DD-WRT/OpenWrt headers, Telnet
Category
NAS Device
Ports: 445, 139, 548, 2049
Signals: Samba, AFP, NFS service banners
Category
Database Server
Ports: 3306, 5432, 27017, 6379, 1433
Signals: MySQL, PostgreSQL, MongoDB, Redis, MSSQL banners
Category
Web Server
Ports: 80, 443, 8080, 8443
Signals: Apache, nginx, IIS, lighttpd headers
Category
Linux Host
Ports: 22, 80
Signals: OpenSSH banner, default web pages

Unmatched hosts are labeled unknown. The fingerprint is based on banner content and port combinations — no active OS fingerprinting probes are sent.

Threat detection

After scanning, the engine automatically evaluates each host against a set of threat rules. Findings are categorized as critical, warning, or info and included in the output report.

critical · port 23
Telnet Exposed
Cleartext remote access. Credential sniffing trivial on-LAN. Should be disabled.
critical · port 21
FTP Exposed
Cleartext file transfer and credentials. Often misconfigured with anonymous login.
critical · port 3306/5432/27017
Database Open
Database port exposed directly on the network. No app-layer boundary. Auth bypass risk.
critical · port 6379
Redis Exposed
Redis default config has no auth. Remote code execution via CONFIG SET dir / cron writes.
warning · port 22
EOL SSH Version
OpenSSH below 8.x or other EOL versions. Known vulns unpatched. Check banner.
warning · port 80
Unencrypted Admin
Admin/management UI over HTTP (no TLS). Credentials sent in cleartext.

CVE lookup

When cve_lookup is enabled, wifi_monitor queries the CIRCL CVE API for each detected service keyword — e.g. openssh, apache, nginx, mysql — and includes matching CVEs in the per-host output.

Results are cached locally for 24 hours to avoid hammering the API on repeated scans of the same network.

# CVE lookup endpoint used
https://cve.circl.lu/api/search/{keyword}

# Example keywords derived from banner grabbing
openssh 7.4       → search: openssh
Apache/2.4.51     → search: apache
nginx/1.18.0      → search: nginx
MySQL 5.7.36      → search: mysql
Redis 6.2.6       → search: redis
ℹ CVE results are keyword-matched, not version-specific. Review CVE details manually to confirm applicability to the exact version found.

Output format

wifi_monitor returns structured JSON — a top-level data object with a hosts array and a summary block.

{
  "success": true,
  "data": {
    "hosts": [
      {
        "ip": "192.168.1.1",
        "mac": "aa:bb:cc:dd:ee:ff",
        "hostname": "router.local",
        "device_type": "router",
        "open_ports": [80, 443, 23],
        "services": {
          "80":  { "banner": "Apache/2.4.51", "http_title": "Router Admin" },
          "443": { "ssl_subject": "CN=router.local" },
          "23":  { "banner": "DD-WRT v3.0" }
        },
        "cves": [
          { "id": "CVE-2021-41773", "summary": "Apache path traversal...", "cvss": 9.8 }
        ],
        "threats": [
          { "level": "critical", "type": "telnet_exposed", "port": 23,
            "detail": "Telnet exposed — cleartext remote access" },
          { "level": "warning", "type": "unencrypted_admin", "port": 80,
            "detail": "Admin interface over HTTP" }
        ]
      }
    ],
    "summary": {
      "total_hosts": 12,
      "hosts_with_threats": 4,
      "critical_threats": 2,
      "warning_threats": 6,
      "scan_time_s": 8.3
    }
  }
}

Examples

Common usage patterns

Passive host discovery only

secV ❯ use wifi_monitor
secV (wifi_monitor) ❯ set mode passive
secV (wifi_monitor) ❯ run 192.168.1.0/24

Deep scan with CVE lookup

sudo secV
secV ❯ use wifi_monitor
secV (wifi_monitor) ❯ set mode deep
secV (wifi_monitor) ❯ set cve_lookup true
secV (wifi_monitor) ❯ set concurrency 100
secV (wifi_monitor) ❯ run 10.0.0.0/24

Single host banner grab

echo '{
  "target": "192.168.1.1",
  "params": { "ports": "top-20", "cve_lookup": false }
}' | python3 wifi_monitor.py | jq '.data.hosts[0]'

Extract only hosts with critical threats

echo '{"target": "192.168.1.0/24", "params": {}}' \
  | python3 wifi_monitor.py \
  | jq '.data.hosts[] | select(.threats[] | .level == "critical")'

Custom port range

secV (wifi_monitor) ❯ set ports 80,443,8080,8443,3000,5000,9200
secV (wifi_monitor) ❯ run 192.168.1.0/24

Requirements

Installation tiers

wifi_monitor is tiered — basic mode works with just Python stdlib, full mode adds scapy for ARP and aiohttp for async CVE requests.

TierPackageFeature
Basicstdlib onlyTCP-ping discovery, sync port scan
StandardscapyARP broadcast host discovery (faster, more accurate)
Fullscapy + aiohttp+ async CVE API lookups (required for cve_lookup)
 
# Standard install (recommended)
pip3 install scapy aiohttp

# Or via install.sh which handles everything
./install.sh
ℹ Scapy requires root for ARP scans. Run sudo secV or use the TCP-ping fallback without root (set mode: passive or drop scapy).
